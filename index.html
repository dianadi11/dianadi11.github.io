Who I am

I'm a platform engineer in Chicago. I got my start running game backends at Zynga — a shared Kubernetes platform behind live-service games with millions of daily players, where being on-call during a title launch teaches you very quickly what "production" means.

Today I work on Altium 365's cloud platform — multi-region EKS across the US, EU, and APAC, where data residency shapes every architecture decision. The work I like most is platform work in the truest sense: building paved roads so development teams ship their own changes safely, instead of filing tickets and waiting on me.

The thing that makes me a little different: I build AI agents that do real operational work. My incident-response agent investigates production alerts before the on-call engineer even opens a laptop — and it's built human-in-the-loop, because the agent suggests and the engineer decides. I care a lot about the difference between AI that demos well and AI you can trust on-call.

Outside of work hours you'll find me in my homelab, breaking and rebuilding things — Istio, Velero, FluxCD — before I'd ever claim them in production.

Projects

The work I'm proudest of — each one a real production problem, and the number it moved.

AI incident-response agent

Problem: every alert started from zero — on-call opened dashboards, pulled logs, and guessed at a cause before doing anything.

I built an assistant on Claude Code with custom skills that does that first pass automatically: when an alert fires, it pulls the related metrics, logs, and recent deploys and drafts a probable root-cause summary for on-call. Deliberately human-in-the-loop — it suggests, the engineer decides.

15–20 min saved per incident
AI agentsClaude CodePythonon-call

Karpenter migration

Problem: fixed node groups meant paying for capacity we weren't using, in three regions at once.

I replaced Cluster Autoscaler with Karpenter across all regions — just-in-time node provisioning and consolidation instead of static groups, sized to what workloads actually request.

~25% EKS compute cut
KarpenterEKScostmulti-region

GitOps delivery at scale

Problem: 50+ microservices deployed by hand-run Helm — slow, error-prone, and hard to audit.

I migrated the fleet to ArgoCD GitOps: automated sync, drift detection, one-click rollback, every deploy reviewed in Git. Paired with OIDC auth so the pipelines run on short-lived credentials — no static keys anywhere.

change-failure rate down 38%
ArgoCDGitOpsOIDCHelm

The slow-query hunt

Problem: a key endpoint was slow, and nobody could say exactly why.

I followed OpenTelemetry traces through the request path until they pointed at an unindexed database lookup behind the endpoint — then got it fixed and watched the latency graph drop.

query latency ~1.2s → ~180ms
